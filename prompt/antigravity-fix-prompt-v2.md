# AntiGravity 画面構造リファクタリング & 座標/UI位置バグ修正プロンプト v2

## 🚨 今回の修正の目的
画面配置の不具合、ドラッグ＆ドロップ時のカード跳ね返り、およびアクションメニュー（UI）の位置ズレ・画面外はみ出しを根本解決するため、画面設計を「単一1000x1000キャンバス ＋ 視点切替方式」へ完全移行し、ドラッグ座標計算とUIクランプ処理を修正します。

---

## 1. 画面レイアウトの改修 (単一1000x1000盤面 ＋ 視点切替)

1. **上下2段分割 (OPPONENT AREA / YOUR FIELD) の完全全廃**:
   - 画面全体を1つのメインキャンバス (1000 x 1000 仮想空間) とし、フィールド・ライフ・リザーブ・トラッシュ・デッキ・バースト等の全ゾーンを画面いっぱいにレイアウトすること。
2. **視点切替ボタン (View Switcher) の設置**:
   - ヘッダーツールバーに 「[自分の盤面] / [相手の盤面]」 のトグル切替ボタンを設置。
   - `currentViewMode` ('MY_BOARD' | 'OPPONENT_BOARD') を Zustand Store で管理。
3. **視点に応じた表示・反転ロジック**:
   - `MY_BOARD`: 自分の所有オブジェクト (`ownerId === localPlayerId`) を正位置 (0度) でメインキャンバスに描画。
   - `OPPONENT_BOARD`: 相手の所有オブジェクト (`ownerId !== localPlayerId`) をメインキャンバスに描画し、描画レイヤーで 180度反転 (x_local = 1000 - x, y_local = 1000 - y) して表示。

---

## 2. カード移動の「左上跳ね返り (Snap Back)」バグの根絶

- **不具合症状**: カードをドラッグ＆ドロップした際、意図した場所に移動せず左上方向に少し跳ね返る / 戻ってしまう。
- **原因と修正指示**:
  - `@dnd-kit` の `onDragEnd` イベントにおいて、ドロップ時の `event.delta` または `event.active.rect` から仮想座標への変換時にスケール（Viewportのアスペクト比維持用CSSスケール）が考慮されていない、または変換失敗時に `(0, 0)` や固定オフセットにフォールバックしている。
  - **対策**:
    1. `Viewport` コンテナの `getBoundingClientRect()` を取得。
    2. ドロップイベントの画面絶対座標 `(clientX, clientY)` を取得し、キャンバス原点 `(rect.left, rect.top)` からのオフセットを計算。
    3. キャンバスの現表示サイズ `(rect.width, rect.height)` で除算し、1000 を乗算することで確実に `0 ~ 1000` の論理座標に変換すること。
    ```typescript
    const x = Math.max(0, Math.min(1000, ((clientX - rect.left) / rect.width) * 1000));
    const y = Math.max(0, Math.min(1000, ((clientY - rect.top) / rect.height) * 1000));
    ```
    4. ドロップ確定後は `moveCard(instanceId, { x, y, zIndex: 1 })` を正しく呼び出し、State 内の `position` を即座に更新すること。

---

## 3. カードアクションUI (メニュー) の位置ズレ & 画面外はみ出し修正

- **不具合症状**: カードをタップ/選択した際、操作メニュー（疲労・反転・デッキ戻し等）がカードから遠く離れた位置に表示され、場合によっては画面外に飛び出して操作不能になる。
- **原因と修正指示**:
  - カードオブジェクトからの相對オフセット計算が、CSSの `transform: scale()` や回転の影響で大きくズレている。
  - **対策**:
    - **選択肢A (画面クランプ処理付きポップアップ)**:
      操作メニューの表示ピクセル座標を決定する際、画面の幅・高さ (`window.innerWidth`, `window.innerHeight`) を考慮し、メニューが画面端から食み出さないようクランプ (`Math.max` / `Math.min`) 処理を必ず適用すること。
    - **選択肢B (画面固定ボトムシート / アクションパネル - **推奨**)**:
      カード選択時の操作メニューを、カードのすぐ隣ではなく **画面下部または画面側面に固定表示されるドロワー/パネル (ActionPanel)** に統一すること。これにより、カードの位置や回転に影響されず、スマホ・PCともに絶対に画面外へ出ないUIを保証できます。

## 4. 動作確認確認項目
1. 「自分の盤面」「相手の盤面」ボタンで表示が切り替わり、画面全域が広く使えていること。
2. どのゾーンへドラッグ＆ドロップしても、放した位置にカードが吸着し、左上へ戻らないこと。
3. カード選択時のアクションメニューが常に画面内に収まり、快適にボタン操作できること。
